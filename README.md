# QQBot 班级群消息助手

[![CI](https://github.com/Gchengs/QQBot-class-assistant/actions/workflows/ci.yml/badge.svg)](https://github.com/Gchengs/QQBot-class-assistant/actions/workflows/ci.yml)

一个跑在自己电脑或服务器上的 QQ 群待办机器人。

它做一件很朴素的事：**把群里那些"记得交""周五前完成""由某某负责"的聊天，自动变成一份能落实到人的待办清单，每周推一次回来。**

不需要公网服务器，不需要第三方协议，不配大模型也能用。

```
QQ 群消息 ──► 抽取 ──► 待办库（JSON）──► 每周推送 / @ 查询
                │
                ├─ 规则版：白嫖，零成本
                └─ 模型版：配个 API Key 更准
```

---

## 为什么写这个

班级群、社团群、项目群都有同一个毛病：**通知发过一遍就沉底了。**

- 有人问"什么时候交来着"，得往上翻三百条；
- 事情明明指定了负责人，最后变成"我以为他会弄"；
- 好不容易有人整理了一份清单，第二天就过期了。

市面上的待办 App 要人手输，没人愿意输。而群里的话本来就已经说了——只是没人把它捡起来。

它干的就是这个"捡"的动作。

---

## 它长什么样

群里 @ 它一下，返回当前所有未完成的事：

```
【待办】共 11 项

本周剩余
1. 第二章整理按宿舍上交〔寝室长〕  11月6日
2. 学籍信息网上核对（学信网注册）〔全体〕  11月9日 14:00

下周
3. 汇总学籍材料交助辅〔副班长〕  11月9日 14:00
4. 高数答疑课（教4-102）〔自愿参加〕  11月15日 18:30

后续
5. 高数期中考试（带学生证或身份证）〔全体〕  11月21日

日期待定
6. 机械制图实验课

销项：#完成 关键词（或 #完成 编号）
```

看三件事就够了：**什么时候、谁的事、还剩几件。**

---

## 三条硬规矩

这个项目最花时间的不是功能，是"不瞎猜"。因为待办清单一旦写错，比没有更糟——写错日期会让人错过 deadline，写错负责人会让真正该做的人以为不关自己事。

**一、日期不猜。** 「今天/明天/下周三」一律按**消息自己的发送时间**换算，不按服务器当前时间。消息没有时间戳，就不解析，直接归到「日期待定」，绝不拿此刻顶替。否则一条 11 月 1 日发的「明天交作业」，在 11 月 5 日补录时会变成 11 月 6 日——凭空造出一个不存在的截止日。

**二、负责人不硬派。** 判定顺序是固定的：@ 了谁 → 谁；正文写了职务（「由副班长汇总」「请纪检委员收齐」）→ 那个职务；两者都没有，才按事项性质查一张对照表；表里也查不到 → 〔全体〕。按内容猜出来的会单独打标记（`owner_inferred`），事后能分清哪条是通知里写明的、哪条是系统以为的。

**三、日期和时刻不跨句配对。** 「11月21日期中考试，15号18:30有一次答疑课」不会拼出「21号 18:30」这种不存在的安排。时刻必须紧贴它自己的日期。

---

## 三条设计取舍

**每月只推 4 次。** QQ 官方给机器人的主动消息配额是每群每月 4 条左右，超了直接报错。所以只保留一个定时推送，并且用「只放行每月 1—28 号」来保证任何月份都恰好 4 次（第 5 个周六自动跳过），不会因为月份长度不同多发或少发。

**没有截止日的事会自己退场。** 「日期待定」（等通知的事）推 3 次、「无期限」（长期有效的事）推 2 次后不再自动出现，否则一条「看课程回放」会跟着周报推一整个学期，人就再也不看周报了。退场只是不推，库里还在，@ 它照样查得到。

**默认不用大模型。** 没配 API Key 时走规则抽取，靠动作词、时间词、职务词和句式判断，零成本、可解释、不会抽风。配了 Key 才走模型，多一层准确率。规则层先筛一遍，能挡掉大量无意义的调用。

## 快速开始

需要 Node.js 18 以上（用到全局 fetch）。

```bash
git clone https://github.com/Gchengs/QQBot-class-assistant.git
cd QQBot-class-assistant
npm install
cp .env.example .env
```

打开 `.env` 填两项，这两个值在 [q.qq.com](https://q.qq.com) → 机器人 → 开发 → 开发设置 里：

```ini
QQ_APP_ID=你的AppID
QQ_APP_SECRET=你的AppSecret
```

启动：

```bash
npm start
```

看到 `机器人已上线` 就连上了。把机器人拉进群，@ 它发一句「群ID」，会返回该群的 OpenID，填进 `.env` 的 `QQ_GROUP_OPENIDS`（留空则自动服务所有已进群）。

Windows 上双击 `启动机器人.bat` 也行，会自动装依赖、崩了自动重启。

### 想要自动抽取待办

去 q.qq.com 后台把「**接收所有消息**」打开，然后在 `.env` 里确认：

```ini
FULL_MESSAGE_MODE=true
```

没开这个权限，机器人只能收到 @ 它的消息，群里聊什么都进不来。这是平台侧的开关，代码绕不过去。

## 群里的用法

| 你发的 | 它做的 |
| --- | --- |
| `@机器人` | 返回全部未完成待办，按紧急度分组 |
| `@机器人 周报` | 返回本周/下周/后续/待定的完整视图（和定时推送同一份） |
| `@机器人 群ID` | 返回本群 OpenID |
| `#待办 周五 交材料` | 手动记一条，最准，不需要模型 |
| `#完成 关键词` | 销项；`#完成 3` 按上次推送的编号销 |
| `#恢复 关键词` | 把自动过期归档的事捞回来 |
| 随便一句普通消息 | 静默入库，不在群里刷屏 |

手动记的那条，负责人也认：

```
#待办 周五 由副班长汇总交助辅   →  〔副班长〕  11月13日
```

## 抽取是怎么工作的

一条群消息进来，先过几道筛子：

1. **清洗**：剥掉 @标记、表情、邮箱、问候语、结尾语气词
2. **分句**：按句号问号分，跳过「已结束/已完成」的句子，挑第一个带动作词的当标题
3. **认日期**：支持 `11月9日`、`11.9号`、`15号`、`明天`、`下周三`、`11月9日～11月27日`（区间两头都记）、`下午三点半`（中文数字）
4. **认人**：@ 优先 → 正文职务（29 个常见职务）→ 内容对照表 → 全体
5. **判状态**：有截止日 = `dated`；等通知 = `pending`；长期有效 = `ongoing`

规则层命中不了的，如果配了 `LLM_API_KEY`，再交给模型判断一次。

想看当前生效的「按内容推断负责人」对照表：

```bash
node src/cli.js owner
```

想改成你们班的实际分工，在 `data/owner-rules.json` 写：

```json
[
  { "keywords": ["学籍", "交助辅"], "role": "副班长" },
  { "keywords": ["青年大学习", "团费"], "role": "团支书" }
]
```

关键词用「包含」匹配，不用写正则。表里没有的一律算全体。

## 目录结构

```
src/
├── index.js            进程入口：连网关、装定时任务
├── config.js           全部配置集中在这，别处不读 process.env
├── cli.js              命令行：导入、销项、预览、自检
├── qq/
│   ├── auth.js         AccessToken 获取与续期
│   ├── api.js          发消息、拿网关地址、拿机器人自身 id
│   └── gateway.js      WebSocket：心跳、重连、事件去重
├── features/
│   ├── ingest.js       群消息入口：判断是不是在 @ 我，然后入库
│   ├── extract.js      规则抽取：日期、职务、标题清洗
│   ├── owner-rules.js  按内容推断负责人的对照表
│   ├── atReply.js      被动回复：所有指令在这
│   ├── digest.js       周报：挑桶、推送、退场计数
│   ├── render.js       渲染：周报、清单、分组、截断
│   ├── remind.js       到期提醒（默认关闭，吃配额）
│   └── course.js       课表提醒（默认关闭）
├── store/              JSON 落盘：待办、群、课程、推送状态
└── utils/date.js       日期解析的全部脏活

scripts/
├── selftest.js         104 项自检，不需要任何 QQ 凭证
├── check-syntax.js     全量语法检查，跨平台（不依赖 bash）
└── check-secrets.js    脱敏体检：openid / IP / 密钥 / 邮箱
```

数据都在 `data/`，纯 JSON，可以直接用编辑器改，也可以随时备份。

## 持续集成

`.github/workflows/ci.yml` 每次 push 和 PR 都会跑，**不需要配置任何 Secret**。

`test` 作业在 Node 18 / 20 / 22 上各跑一遍：

1. `npm run check` —— 全部 .js 过一遍 `node --check`
2. `npm test` —— 104 项自检，覆盖日期解析（中文数字、区间、区间首尾、相对时间的基准）、抽取规则（闲聊挡掉、职务识别、标题清洗）、同周去重、退场计数、渲染截断
3. `npm test` 再跑一遍 —— 自检脚本会往 `data/_selftest` 写临时数据，如果它没打扫干净，第二次就会读到残留而变红。这一步专门盯这个回归。

`secrets` 作业是本仓库特有的：它脱胎于一个真实班级群的部署实例，一旦有人把 `data/todos.json` 或 `.env` 提交上来，泄露的是整群的人和聊天原文。

1. `scripts/check-secrets.js` 扫内容：32 位大写十六进制（群/用户 openid）、16 位以上长数字（用户 id）、非本机 IP、`sk-`/`ghp_`/私钥头，命中即失败；邮箱和主机名只报警告（文档举例需要人工判断）
2. `git ls-files` 查跟踪：`.env`、`data/*.json`（`*.example.json` 除外）、`*.tar.gz` 一旦被提交，直接用 `::error` 标在出问题的文件上

本地提交前想跑同一套：`npm run check && npm test && npm run secrets`。

## 发版

版本号只有一个来源：`package.json` 的 `version`。tag 和 Release 都跟着它走，**别手写 `git tag`**，否则三者迟早对不上。

```bash
git status --short                            # 有未提交改动时 npm version 会直接失败
npm run check && npm test && npm run secrets  # CI 会在远端再跑一遍，本地先过更省事
npm version patch                             # 1.0.0 → 1.0.1
git push --follow-tags
```

`npm version` 一次做三件事：改 `package.json`、提交一次、打一个 **annotated** tag。两个细节容易搞混：

- **tag 名带 `v`（`v1.0.1`），提交信息不带（`1.0.1`）**，这是 npm 的默认行为，不是笔误
- 推的时候必须用 `--follow-tags`，它只推 annotated tag——`npm version` 打的正好是这种；而手动 `git tag v1.0.1` 打出来的是轻量标签，`--follow-tags` 推不上去，得用 `git push --tags`

工作区不干净时它会直接拒绝（`npm error Git working directory not clean.`），所以第 1 步不是可选的。

推完去建 Release：**Releases → Draft a new release → 选刚推上去的 `vX.Y.Z` → 写说明 → Publish**。

CI 里没有自动建 Release 的步骤，这是有意的：「这次改了什么、为什么」没法交给脚本写。

### 三种版本号怎么选

| 改了什么 | 版本 |
| --- | --- |
| 修 bug、改文案、调默认配置 | `patch` |
| 新增群指令、新增 `.env` 配置项、新增抽取规则 | `minor` |
| 改了 `data/` 下 JSON 的字段结构 | `major` |

最后一条最容易漏。待办库是纯 JSON 落盘，**用户手里有数据**，字段改名或删字段不是「就改了几行代码」的事。

> **动数据结构之前先看这条。** `data/*.json` 里有个 `version: 1` 字段，但代码目前**只写不读**——`load()` 里直接把它覆盖成 1，没有任何迁移逻辑。真改了字段名，老数据不会报错，只会让那一批待办的负责人、日期读成空值，静默出错比崩溃更难查。所以：
>
> 1. 改之前让用户先 `npm run cli -- backup` 留一份快照
> 2. 补一个按 `version` 分支的迁移函数，把 `version` 从「装饰品」变成真的开关
> 3. 这两件事做完才算 `major`，只改代码不算

## 部署到服务器

WebSocket 模式下进程必须常驻。树莓派、旧笔记本、云服务器都行。

```bash
npm run pack                                  # 打成一个包（含依赖，服务器上不用联网装包）
scp qqbot-class-assistant.tar.gz root@你的服务器IP:/tmp/
scp deploy/install.sh root@你的服务器IP:/tmp/
ssh root@你的服务器IP 'bash /tmp/install.sh'
```

`install.sh` 会装 Node、建 `qqbot` 用户、装成 systemd 服务并设开机自启。

之后更新代码：

```bash
npm run pack -- qqbot-class-assistant-update.tar.gz
scp qqbot-class-assistant-update.tar.gz root@你的服务器IP:/tmp/
ssh root@你的服务器IP 'rm -rf /tmp/upd && mkdir -p /tmp/upd \
  && tar -xzf /tmp/qqbot-class-assistant-update.tar.gz -C /tmp/upd \
  && bash /tmp/upd/deploy/update.sh'
```

`update.sh` 会先备份 `src` 和 `.env`，只替换代码，重启后跑一次自检。

## 已知限制

说在前面，省得你踩坑：

1. **拿不到机器人进群之前的历史消息。** QQ 官方只推事件，没有「拉取群历史消息」的接口。清单从机器人进群那天开始积累，之前的只能手动补。
2. **主动消息有配额。** 每群每月 4 条左右，超了报 `40073001`。所以定时推送只留了周报一个，其他提醒默认关闭。
3. **主动消息可能被静默拒绝。** 群里可以关掉「允许主动发送」，关掉之后报 `40034105 无权限`。这时候走 `@机器人 周报`，被动回复不占配额，100% 能送达。
4. **规则抽取做不了摘要。** 它只能从长通知里挑出最像待办的那一句原话当标题，不会概括成一句人话。想干净就手动 `#待办`。
5. **识别不了具体人名。** 系统不知道谁是张三、担什么职务。正文写职务能认，写名字认不出来。
6. **学习通没有开放 API。** 课表只能手动喂。

## 排障

| 现象 | 原因 |
| --- | --- |
| 启动报「缺少必填配置」 | `.env` 没填 AppID/AppSecret |
| 连上了但收不到消息 | 机器人没进群；后台事件订阅没开；或没开「接收所有消息」 |
| @ 了没反应 | 可能在群里 @ 了另一个同名机器人；或后台事件订阅方式不是 WebSocket |
| 定时推送没反应 | 没有未逾期待办；进程没跑；主动消息被关；或当月配额用完 |
| 群里聊很多，一条没进库 | `FULL_MESSAGE_MODE=false`，或后台没开「接收所有消息」 |
| 日期算错了 | 相对日期按消息发送时间算，不按当前时间；无时间戳则归「日期待定」 |
| 某条待办推两次就消失 | 它没有截止日，推够次数自动退场，改 `PENDING_SHOW_LIMIT` / `ONGOING_SHOW_LIMIT` |
| 回复报 11255 | `QQ_GROUP_OPENIDS` 填成了群号（清空即可，会自动登记） |
| 消息带链接发不出 | 后台需预配置消息 URL 白名单 |
